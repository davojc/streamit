# StreamIt v1.1 — Screens and Simulation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver four things:
- rebuild the StreamIt window to the approved mockups;
- add Start service now and an NDI counter for every video;
- close the three issues left open in v1;
- add an in-app simulation mode that runs the real engine against pretend equipment and a pretend YouTube.

**Architecture:**
- **Core (`streamit-core`).** The engine gains the snapshot fields the screens need: video and countdown progress, on-air time, activity and the simulation flag. It also gains the Start-service-now behaviour.
- **New crate (`streamit-sim`).** It implements every core device trait against one shared pretend world. The world has speed and fault controls, and a control API for the Simulation tab.
- **App (`streamit-app`).**
  - A `Session` abstraction owns one engine plus its devices. Switching real ↔ simulation is a session swap behind a stable front channel that the window and the Stream Deck use.
  - The egui UI is rebuilt from pure, unit-tested view functions (`view.rs`) plus restyled rendering.

**Tech Stack:** Rust 1.98 (edition 2024), tokio, egui/eframe 0.37 (existing), tracing / tracing-appender, plus the `mp4` crate for reading clip lengths.

**Specs:**
- `docs/superpowers/specs/2026-10-23-streamit-screens-and-simulation-design.md` (this release).
- `docs/superpowers/specs/2026-10-21-streamit-workflows-design.md` (v1; still binding where not changed).

**Mockups (binding for layout and content):** https://claude.ai/artifact/PEFzDp4XbnGF48ZGoANrFj. The screens are:

4. Live, video playing

## Global Constraints

### Colours, fonts and labels
- **Colours:** ground `#0E1116`; panels `#161B22`; panel border `#262D36`; header `#12161C`; text `#E6EAF0`; muted text `#9AA4B2`; on-air red `#E5484D`; OK green `#3DD68C`; warning/countdown/simulation amber `#F5A524`; video/selection blue `#4C9AFF`.
- **Fonts:** Barlow Semi Condensed (labels and headings), Atkinson Hyperlegible (body), JetBrains Mono (times). All bundled in the binary; nothing fetched at run time. Each must come with its OFL licence file.
- **Tabs:** Service, Videos, Settings, plus Simulation in simulation mode only.
- **Service steps:** Prepare → Countdown → Live → End service.

### Behaviour that must hold
- **Start service now:** one sequence. If the broadcast is not public, make it public *in parallel with* the T-0 cut, and never wait for YouTube before cutting. A go-public failure gives a warning plus Offer::GoPublic, shown as **Retry going public**.
- **NDI counter:** while any video plays (the countdown or a roll-in) it shows `M:SS` remaining, updated every 100 ms, and clears when the video ends or stops. Its source name is "StreamIt Countdown".

### Simulation
- **Switching:**
  - The switch lives only in Settings → Equipment.
  - It is allowed only while the stage is Idle or Ended and no job is running.
  - The app always starts in real mode.
  - Switching to real does the normal read-only startup.
- **No real device code runs in simulation:** no ATEM, VideoHub, Web Presenter, DeckLink, NDI, YouTube or mDNS clients are constructed.
- **Separate from real data:**
  - Uses the real settings file.
  - Keeps mic levels in `sim-levels.toml` beside `config.toml`.
  - Writes logs to a `sim-streamit.log.*` daily file, not the real log.
- **Always visible:**
  - A striped amber banner on every screen reading "SIMULATION — nothing here is live. No equipment or YouTube is touched.", linking to Settings › Equipment.
  - The window title gets "— SIMULATION".
  - The Stream Deck phase key shows "SIM" under the stage.
- **Pretend timing:** at speed 1×, ATEM mixes take 1 s (`program()` reports the old source until the mix completes). VideoHub routes apply after 1 s. Web Presenter goes Connecting → Streaming after 3 s. YouTube health turns Good 5 s after streaming starts, and its transitions take 2–3 s.
- **Speed:** 1×, 4× or 10×. It scales pretend-device delays, video playback, and these config durations: VideoHub settle, closing hold, mic fade. Core's built-in retry gaps are not scaled. **[ruling S1: core has no injectable clock; scaling those needs a core rewrite that is out of scope]**
- **Clip length:** read from mp4/mov files with the `mp4` crate. If it can't be read, the clip lasts 30 s.

### Other
- Remove every mention of ProPresenter from README.md, `docs/rehearsal.md` and the v1 spec.
- Disk on E: is tight. Reuse `target/` and never run `cargo clean`.

## Review Focus

1. **Settings point at real addresses while in simulation** → no socket is ever opened. Task 6 `simulation_builds_no_real_devices` (a factory spy panics if a real constructor is called).
2. **Switch pressed while something runs** (including during Prepare, where the stage still reads Idle) → refused with "Finish or end the service first". Task 6 `switch_refused_while_job_runs`.
3. **A clip whose length can't be read** (a truncated file, `.mkv`, or an unreadable path) → plays for 30 s and nothing errors. Task 5 `unreadable_clip_lasts_30s`.
4. **"Crash & restart app" pressed during a video** → the new engine offers Recover, and Recover restores input 8 and the mics. Task 5 `restart_mid_video_offers_recover` (sim world + core assess).
5. **Start service now pressed twice, or while going public hangs** → exactly one T-0 cut; the stage reaches Live without waiting for YouTube. Task 2 `start_service_now_twice_one_cut` and `start_service_now_does_not_wait_for_youtube`.

### Task 6: Sessions and the real ↔ simulation switch

**Files:**
- Create: `crates/streamit-app/src/session.rs`

**Interfaces:**
- **Mode:** `pub enum Mode { Real, Simulation }`.
- **Factory:** `pub trait DeviceFactory: Send + Sync { async fn build(&self, c: &Config) -> Built; }`, where `Built { devices: Devices, health: Vec<(DeviceKind, DeviceHealth)>, probes: Option<Probes>, sim: Option<SimControl> }`.
  - `RealFactory` wraps the existing `wiring::build`.
  - `SimFactory` wraps `streamit_sim`, with no mDNS and no sockets.
- **Front:** the stable handle the window and the deck hold, `pub struct Front { pub tx: mpsc::Sender<Command>, pub rx: watch::Receiver<Snapshot>, pub mode: watch::Receiver<Mode>, pub sim: watch::Receiver<Option<SimControl>> }`. Commands are forwarded to the current session's engine, and snapshots are forwarded from it.
- **Sessions:** `pub struct Sessions` with:
  - `async fn start(real: Arc<dyn DeviceFactory>, sim: Arc<dyn DeviceFactory>, config, paths) -> (Sessions, Front)`, which starts in Real;
  - `async fn switch(&self, to: Mode) -> Result<(), SwitchRefused>`.
  - `switch` is allowed only if the latest snapshot has `stage ∈ {Idle, Ended}` and `job.is_none()`. Otherwise it returns `SwitchRefused("Finish or end the service first")`.
  - Switching stops the old engine, health poll and device tasks, builds the new devices, then spawns the new engine with `simulation = (to == Simulation)` and levels from `sim-levels.toml` or `levels.toml`.
- **Logging:** `logging::init` gains a second appender `sim-streamit.log` (daily). Events inside the `simulation` tracing span go only there; all other events go only to the real log. The session runs its engine inside that span when simulating.
- **Deck:** the phase key renders the stage text and, beneath it, "SIM" when `snap.simulation`.
