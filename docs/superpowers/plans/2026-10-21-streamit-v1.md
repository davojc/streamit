# StreamIt v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a Windows desktop app in Rust that runs the church's YouTube live stream from a Stream Deck XL. It covers Prepare, Countdown, automatic T-0, roll-in videos and End Service, driving two ATEMs, a VideoHub, a Web Presenter 4K, a DeckLink SDI 4K, an NDI counter and the YouTube API.

**Architecture:**
- The core crate holds everything with no I/O: configuration, device traits, and the workflow sequencers (Go Live, roll-ins, End, recovery). These are tested against recording fakes, with tokio's paused clock for timing.
- Each device gets its own crate implementing one core trait. Each is unit-tested at the protocol level and checked against real hardware through a `streamit probe` subcommand.
- The app crate connects everything:
  - a single engine task takes commands from the Stream Deck and the egui window, and publishes state snapshots;
  - discovery, settings and logging also live here.

**Tech Stack:**
- **Language and runtime:** Rust stable 1.98 (x86_64-pc-windows-msvc), tokio, async-trait.
- **Configuration and errors:** serde + toml, directories, thiserror/anyhow.
- **Logging:** tracing + tracing-appender.
- **Device and service clients:**
  - gstreamer-rs (DeckLink playout and the NDI counter);
  - elgato-streamdeck (with the image, ab_glyph and imageproc crates for drawing keys);
  - reqwest + oauth2 (YouTube Data API v3);
  - mdns-sd (device discovery).
- **App window:** eframe/egui.
- **Tests:** wiremock and tokio test-util.

**Spec:** `docs/superpowers/specs/2026-10-21-streamit-workflows-design.md`

## Global Constraints

**Platform**
- Target: Windows 11 x64, Rust stable 1.98, MSVC toolchain. Rust edition 2024.
- External runtimes the user installs, documented in `README.md`:
  - GStreamer 1.24+ MSVC 64-bit, **complete** install, including the `decklink` plugin and the gst-plugins-rs `ndi` plugin;
  - NDI 6 Runtime;
  - Blackmagic Desktop Video (the DeckLink driver).

**Video**
- Video format everywhere: **1080p29.97**.

**Stream ATEM** — Television Studio HD8 ISO, 192.168.4.123
- Fairlight audio. The mic/hall source is input **1001**, and it uses the stereo source of that input.
- **Input 8 is shared by Camera 8 and the DeckLink, through the VideoHub.**
- Live inputs default to **1, 2, 3**. The default live input is **1** (the safe wide shot).
- The opening and closing holding images are **two different stills**, shown through a media player.

**Screens ATEM** — Television Studio HD, 192.168.4.98
- DeckLink input: **8**.

**Other devices**
- VideoHub: 40×40 at 192.168.4.100, port 9990.
- Web Presenter 4K: 192.168.4.93, control port 9977.
- These addresses are only defaults. Discovery and role assignment always win.

**Timings**
- Go public at **T-10s**.
- Closing hold **10 s**.
- Mic fade **1 s**, down to **−∞**. The Fairlight floor is **−100 dB**.
- VideoHub settle time **1.5 s**.

**NDI counter**
- 1080p full frame, **yellow numbers on black**.

**Behaviour rules**
- **Startup:** never change any device automatically. Read device states and offer Recover, Go Public and Go Live keys instead.
- **Warnings never block** the operator.
- **Input 8:** never re-route it while it is on Stream ATEM program.
- **YouTube:**
  - Never rebind, or change Auto Start/Auto Stop, silently. Warn, then offer a one-press fix.
  - Never use Auto Start. Auto Stop stays **on** as a safety net.
- **After a video:** return to **Preview** unless the video has a return input. The same applies to the Screens ATEM.
- **One video at a time.** A second press is ignored, and its key flashes.
- **The cue list:**
  - holds at most **14 videos** in v1 (two rows of 7 keys);
  - keeps the order the videos were added.
- **Companion must not be running on the playout PC.**
- **Do not commit `companion/`.** It is an export from another machine and may contain credentials.

## Review Focus

1. **A device drops mid-sequence**, e.g. the VideoHub disconnects after the route to the DeckLink but before the restore.
   - Expected: the sequence keeps going as far as it can, the error is logged, and **Recover** lights.
   - Test: Task 5 `device_error_mid_rollin_lights_recover`.
2. **The operator presses keys in an odd order**: Countdown twice, End Service during a video, Prepare while live.
   - Expected: nothing double-fires.
   - End during a video stops the video first, then runs End.
   - Tests: Task 8 `double_countdown_ignored`, `end_during_video_stops_video_first`, `prepare_while_live_ignored`.
3. **A video file can't be played**: corrupt, a missing path, or no audio track.
   - Expected: the key shows an error, and no ATEM or VideoHub change happens.
   - Files in another format (25p, 4K, 48 vs 44.1 kHz) are converted, not rejected.
   - Tests: Task 5 `load_failure_switches_nothing`; Task 13 `pipeline_converts_any_input`.
4. **YouTube is unhappy**: expired sign-in, no upcoming broadcasts, the broadcast was deleted, or the transition is refused.
   - Expected: the status key turns red with a reason, and the manual Go Public / End Broadcast keys stay usable.
   - The local sequence (ATEMs and encoder) still runs.
   - Tests: Task 4 `go_public_failure_retries_and_flags`; Task 6 `youtube_failure_still_stops_encoder`; Task 12 `expired_token_reports_signin_required`.
5. **The countdown file is shorter than the go-public offset**, or its duration is unknown.
   - Expected: go public immediately at countdown start, with a warning.
   - Test: Task 4 `short_countdown_goes_public_immediately`.

### Task 4: Go Live sequencer (Stage 0–3)

**Files:**
- Create: `crates/streamit-core/src/golive.rs`

**Interfaces:**
- Consumes: `Devices`, `Config`, `audio::{fade, LiveLevels, Target}`.
- Produces:
  - `Readiness { Ready, Waiting(String), Warning(String) }`
  - `Stage { Idle, Prepared(Readiness), Countdown { remaining: Duration, public: bool }, Live, Ending { remaining: Duration }, Ended }`
  - `Stage0Report { signed_in: bool, broadcasts: Vec<BroadcastSummary>, selected: Option<String>, check: Option<BroadcastCheck>, device_errors: Vec<String> }`
  - `async fn stage0(d: &Devices) -> Stage0Report`, which picks the first upcoming broadcast as `selected`.
  - `async fn prepare(d: &Devices, c: &Config, bid: &str, levels: &mut LiveLevels, progress: impl Fn(Readiness)) -> Readiness`, in this order:
    1. capture the live levels;
    2. set the media player still to `opening_still`;
    3. set preview to the media-player input;
    4. Auto;
    5. fade the mics to Floor over `fade`;
    6. start the encoder;
    7. poll health every 2 s for up to 60 s until `Good`;
    8. if `life_cycle` is not already `testing`/`live`, transition to `Testing`.

    It returns `Ready`, or `Warning(reason)` on a timeout or error. It never panics or aborts early.
  - `async fn countdown(d: &Devices, c: &Config, bid: &str, ready: &Readiness, levels: &LiveLevels, cancel: CancellationToken, progress: impl Fn(Stage)) -> Result<CountdownOutcome>`, in this order:
    1. load `countdown_file` at 0 dB;
    2. Screens preview = `decklink_input`, then Auto;
    3. play;
    4. every 100 ms, update the counter with `duration - position`;
    5. when `remaining <= go_public_offset`, call `go_public` once;
    6. on `PlayerEvent::Ended`, run `t0`.

    `CountdownOutcome { Live, Stopped }`. Cancelling stops the player, clears the counter and sets Screens preview = `t0_input` then Auto. YouTube is left as it is.
  - `async fn go_public(d: &Devices, bid: &str) -> Result<()>`: transition to `Live`. On error it retries 3 times, 2 s apart, then returns `Err`.
  - `async fn t0(d: &Devices, c: &Config, levels: &LiveLevels) -> Result<()>`:
    1. if Stream preview is not in `live_inputs`, set preview = `default_live_input`;
    2. Stream Auto;
    3. fade the mics to Live;
    4. Screens preview = `t0_input`, then Auto;
    5. clear the counter.

  (`CancellationToken` comes from tokio-util.)

### Task 5: Cue list and roll-in sequencer

**Files:**
- Create: `crates/streamit-core/src/rollin.rs`

**Interfaces:**
- Consumes: `Devices`, `Config`, `audio`.
- Produces:
  - `Destination { HallAndOnline, HallOnly, OnlineOnly, AudioOnly }`
  - `Cue { path: PathBuf, name: String, destination: Destination, gain_db: f32, return_input: Option<u16> }`
  - `CueList` with:
    - `push(cue) -> Result<(), CueListFull>` (maximum 14, order kept);
    - `remove(i)`, `move_up(i)`, `move_down(i)`, `get(i)`;
    - `state: Vec<CueState>`, where `CueState { Cued, Playing, Played, Error(String) }`.

    The cue list is saved with Config (`Config.cues: Vec<Cue>`), so it survives a restart.
  - `RollinOutcome { Finished, Stopped, Refused(String), Failed { recover_needed: bool, reason: String } }`
  - `async fn play(d: &Devices, c: &Config, cue: &Cue, levels: &mut LiveLevels, stop: CancellationToken, unmute: Arc<Notify>) -> RollinOutcome`, in this order:
    1. `player.load(path, gain_db)`. On error → `Failed{recover_needed:false}`, with **no** device calls.
    2. If the Stream ATEM is involved (HallAndOnline, OnlineOnly, AudioOnly):
       1. If the VideoHub numbers are unset (0) → `Refused("VideoHub not configured")`.
       2. If Stream program == `decklink_input` → `Refused("Input 8 is on air")`.
       3. `prev = hub.route_of(input8_output)`.
       4. `hub.route(input8_output, decklink_input)`.
       5. Sleep `settle`.
       6. Capture the live levels.
    3. Switch per the spec table:
       - Stream picture: preview = 8, then Auto.
       - Input 8 audio: `set_audio_on(8 stereo, true)` + `set_audio_level(8, gain 0)`.
       - Mics: fade to Floor.
       - Screens: preview = `decklink_input`, then Auto.
       - **HallOnly** touches no Stream audio.
    4. `player.play()`.
